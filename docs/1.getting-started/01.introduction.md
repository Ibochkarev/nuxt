Nuxt is a free and [open-source framework](https://github.com/nuxt/nuxt) with an intuitive and extensible way to create type-safe, performant and production-grade full-stack web applications and websites with [Vue.js](https://vuejs.org).

Nuxt has no vendor lock-in: deploy your application [**everywhere, even on the edge**](/blog/nuxt-on-the-edge).

::tip
If you want to play around with Nuxt in your browser, you can [try it out in one of our online sandboxes](/docs/getting-started/installation#play-online).
::

## Automation and Conventions

Nuxt uses conventions and an opinionated directory structure to automate repetitive tasks, so you can focus on building features. The configuration file still lets you customize and override the default behavior.

- **File-based routing:** define routes based on the structure of your [`app/pages/` directory](/docs/directory-structure/app/pages). This can make it easier to organize your application and avoid manual route configuration.
- **Code splitting:** Nuxt automatically splits your code into smaller chunks, which can reduce the initial load time of your application.
- **Server-side rendering by default:** Nuxt comes with built-in SSR capabilities, so you don't have to set up a separate server yourself.
- **Auto-imports:** write Vue composables and components in their respective directories and use them without imports, with tree-shaking and optimized JS bundles.
- **Data-fetching utilities:** Nuxt provides composables to handle SSR-compatible data fetching, with different strategies.
- **Zero-config TypeScript support:** write type-safe code without having to learn TypeScript with our auto-generated types and `tsconfig.json`.
- **Configured build tools:** Nuxt uses [Vite](https://vite.dev) by default for hot module replacement (HMR) in development and for bundling your code for production with best practices built in.

## Server-Side Rendering

Nuxt has built-in server-side rendering (SSR) by default, without extra server configuration, which has benefits for web applications:

- **Faster initial page load time:** Nuxt sends a fully rendered HTML page to the browser, which displays immediately. This can provide a faster perceived page load time and a better user experience (UX), especially on slower networks or devices.
- **Improved SEO:** search engines can index SSR pages more easily because the HTML content is available immediately, with no client-side JavaScript required to render it.
- **Better performance on low-powered devices:** SSR reduces the JavaScript downloaded and executed on the client. This helps low-powered devices that struggle with heavy JavaScript applications.
- **Better accessibility:** the content is immediately available on the initial page load, improving accessibility for users of screen readers and other assistive technologies.
- **Easier caching:** you can cache pages server-side, which further improves performance by reducing the time to generate and send content to the client.

Nuxt also supports static rendering of the whole application on a static host with `nuxt generate`. Disable SSR globally with the `ssr: false` option, or use hybrid rendering with the `routeRules` option.

## Server Engine

The Nuxt server engine, [Nitro](https://nitro.build/), unlocks new full-stack capabilities.

It generates your server API by reading files from `server/api/` and server middleware from `server/middleware/`.

In production, Nitro builds your app and server into one universal `.output` directory. This output is light: minified and stripped of Node.js modules (except polyfills). You can deploy it on any system supporting JavaScript, such as Node.js, Serverless, Workers, Edge-side rendering or purely static.

## Architecture

Nuxt is composed of different [core packages](https://github.com/nuxt/nuxt/tree/main/packages):

- Core engine: [nuxt](https://github.com/nuxt/nuxt/tree/main/packages/nuxt)
- Bundlers: [@nuxt/vite-builder](https://github.com/nuxt/nuxt/tree/main/packages/vite), [@nuxt/rspack-builder](https://github.com/nuxt/nuxt/tree/main/packages/rspack) and [@nuxt/webpack-builder](https://github.com/nuxt/nuxt/tree/main/packages/webpack)
- Command line interface: [@nuxt/cli](https://github.com/nuxt/cli)
- Server engine: [nitro](https://github.com/nitrojs/nitro)
- Development kit: [@nuxt/kit](https://github.com/nuxt/nuxt/tree/main/packages/kit)

Read each concept to get a full picture of Nuxt capabilities and the scope of each package.
